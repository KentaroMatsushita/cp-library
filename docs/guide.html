このサイトについて

競技プログラミング用コードをカテゴリ別に掲載します。「説明あり」はコードを読んで仕様・計算量・注意点を整理したもの、「テスト対象・成功」は現在のコードと一致するオフライン検証の結果があるものです。「未レビュー」は既存ファイルの目録であり、説明・レビュー・動作保証は未完了です。

ライブラリの全 API を検証しているわけではありません。各ページとテスト実装で対象を確認してください。外部ジャッジでの AC バッジは付けていません。

C++ での使用方法

新しい幾何コードは C++17 以上で単独 include できます。既存の .cpp は提出用スニペットで、標準ヘッダ、using namespace std、Graph や ll などの型、rep/all などのマクロを呼出し側で用意する実装が多くあります。同名クラス・同名関数の別実装を同時に include しないでください。C++20 の auto 引数を使う既存ファイルもあります。

#include "geometry/geometry.hpp"
int main() {
    cp_geometry::ConvexPolygon p({{0,0},{2,0},{2,2},{0,2}});
    return p.contains({1,1}) == cp_geometry::IN ? 0 : 1;
}

コンパイル例：g++ -std=c++17 -O2 -iquote /path/to/cp_library main.cpp。元フォルダには vector という作業ファイルがあるため、標準ヘッダ探索にも影響する -I の代わりに -iquote を使います。

ローカル検証

python3 tools/test.py --sanitize
python3 tools/build_docs.py
python3 tools/check_docs.py
python3 -m http.server 8000 --directory _site

必要なのは Python 3.10 以上と g++（C++17）です。追加の Python パッケージや外部ジャッジへのアクセスは不要です。CXX=clang++ python3 tools/test.py --sanitize で別コンパイラを指定できます。最初の失敗で停止し、古い成功結果は破棄します。

固定シードのランダム比較テスト、境界ケースの回帰テスト、AddressSanitizer と UndefinedBehaviorSanitizer を実行します。ソースとテストの SHA-256 を記録し、更新後に古い結果が成功表示へ流用されないようにしています。テスト中にコードが変化した場合も失敗扱いです。

変更するとき

  1. 該当コードと verify/*.test.cpp のテストを変更する。
  2. docs/catalog.json の仕様・計算量・前提条件・利用例・テスト対象を更新する。
  3. 上記コマンドでテスト、ページ生成、リンク検証を行う。
  4. GitHub に push する。GitHub Actions が再検証し、main の成功したビルドを GitHub Pages に配置する。

公開対象

tools/library.py に指定したライブラリディレクトリ直下の .cpp/.hpp/.h と明示したテンプレートだけをコピーします。コンテストの回答、実行ファイル、入力・出力、画像、ローカル設定、AHC の作業フォルダはサイトに含めません。新しいカテゴリは明示的に追加してください。ソース中の元作者・出典コメントは保持します。

GitHub Pages の初期設定

リポジトリの Settings → Pages → Build and deployment の Source を GitHub Actions にします。Settings → Secrets and variables → Actions → Variables に PUBLISH_LIBRARY_PAGES=true を追加します。以後は main への push 時に検証と公開が走ります。pull request では検証とサイトビルドだけ実行します。非公開リポジトリの Pages 利用可否は GitHub の契約によります。公開サイトを作るためだけに、作業ファイルや履歴を含む元リポジトリ全体を公開する必要はありません。

公開の仕組みは GitHub 公式のカスタムワークフローに従います。
